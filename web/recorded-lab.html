      # Default suite checks every expected outcome, including the known bug
python3 -I -S scripts/run_local.py --output local-results.json

# Per-handler check: repaired should pass (exit 0)
python3 -I -S scripts/run_local.py --case crash-after-fulfillment --mode repaired

# Per-handler check: vulnerable should violate the invariant (exit 1)
python3 -I -S scripts/run_local.py --case crash-after-fulfillment --mode vulnerable

      Per-handler exit codes: 0 passed, 1 violation, 2 incomplete, 3 unresolved. The default suite verifies expected outcomes; reproducing the known violation does not make the vulnerable handler safe.

      Local scope: direct invocation and an in-memory ledger exercise the code and assertions. They do not emulate AWS scheduling, queue visibility, throttling, or service failure behavior. The comparison above displays the selected AWS-format observations.

      A deliberately small lab

      The retry is real.
      The fulfillment is simulated.

      01

      Deliver & deliberately crash

      SQS invokes Lambda. The receiver commits a durable fulfillment receipt. Then the worker raises an error before returning success.

      02

      Let AWS retry

      The message becomes visible again. The vulnerable handler creates another receipt. The repair supplies a stable order key to the same receiver.

      03

      Observe independently

      The runner queries DynamoDB separately from worker logs, confirms redelivery, and checks a bounded period with empty queues.

      i

      What browser checks mean Supported internal consistency rules are checked locally. AWS origin remains unauthenticated, and the browser does not execute the handlers or run the full archived verifier. Receiver-owned idempotency does not guarantee exactly-once SQS delivery or an external shipping action.

      Observation limits & spending bounds

      At most 6 messages per runner invocation; a bounded wait; short log retention; capped database throughput; processing expiry. These reduce costs, but are not a hard billing cap.

      Exported evidence is not cryptographically signed by AWS. The offline verifier checks consistency, and SQS queue counts are approximate. Missing evidence stays incomplete; contradictory evidence stays unresolved.
